01

业务要求的准确含义

百分位是位置，右偏是数据形态；两者结合用于获得更可靠的异常阈值。

一句话解释

在同类样本中按实际答题时长排序，用第 5、第 95 百分位作为过快和过慢的边界，而不是使用对称的“平均值 ± 标准差”判断。

偏右偏分布

大量样本集中在较短区间，少量超长记录把右侧尾部拖得很长。

P百分位

P05 表示约 5% 的记录更短；P95 表示约 95% 的记录不超过该时长。

✓业务结果

过快答卷进入人工审核；超长题目按截尾或已确认的补偿规则处理。

02

为什么原正态规则容易失效

原始答题时长不是左右对称数据，均值和标准差会被极端值显著影响。

原规则Z = (x − μ) / σ
P = Φ(Z)隐含前提：原始时长近似服从正态分布。
问题右尾极端值 ↑ → μ、σ 同时被拉高正常范围被放大，过快或过慢记录仍可能被判为正常。

“全部显示正常”的重点排查项

问题典型表现修正方式
P 值单位不一致接口返回 0.05，页面按 5 比较全链路统一使用 0～1，展示时再乘 100%
时长单位不一致实际值为秒，阈值为分钟计算层统一存秒，展示层负责换算
比较方向错误P05、P95 均未命中答卷过快用 ≤P05，题目超长用 ≥P95
阈值分组不一致阈值存在但匹配不到计算和审核共用同一个 group_key
失败默认正常无阈值或样本不足仍显示正常改为“待定”，禁止静默降级为正常
03

推荐方法：经验百分位

直接使用真实样本排序，不要求原始数据符合任何特定分布。

经验累计分位Pᵢ = F̂(xᵢ) = (1/n) · ∑ 𝟙(xⱼ ≤ xᵢ)𝟙(条件)成立取 1，否则取 0。
分位阈值Tlow = Q0.05(X)
Thigh = Q0.95(X)Qₚ 表示样本排序后的第 p 百分位。
推荐原因

能够忠实反映右偏、长尾和多峰数据，不需要先验证正态性；规则结果也容易向业务解释。

对数变换uᵢ = ln(1 + xᵢ)
Zᵢ = (uᵢ − μlog) / σlog对数空间更接近对称分布。
原始尺度阈值Tₚ = exp[μlog + σlogΦ⁻¹(p)] − 1仅在业务必须使用平滑概率曲线时采用。

题目级规则：处理异常超长单题

避免离开页面、切到后台等行为把整份答卷时长异常拉长。

建议分组：车型 × 问卷版本 × 题目编号；渠道差异明显时再加入渠道。不同题型不能混合计算。

题目上限T题,95 = Q0.95({x₁,…,xₙ})xᵢ 为单次题目实际作答时长。
异常条件xᵢ > T题,95
或 P题,i ≥ 95%阈值应支持后台配置。

异常题目时长的处理选择

方案公式评价
原业务补偿xᵢ* = μ题 / 3便于历史兼容，但可能明显低估答卷时长

P95 截尾xᵢ* = min(xᵢ,T题,95)推荐，稳定且容易解释

分组越细越精准，但样本不足时百分位会不稳定，必须配置回退链路。

→

→
三级问卷类型 × 近 90 天基线
有效样本量处理方式
n ≥ 200使用当前细分组的百分位阈值

07

冷启动与数学自锁防护

没有历史样本时，n、μ、σ 和百分位阈值均不存在，必须先建立基线，不能直接执行 μ/3 补偿。

风险结论

如果系统在 n=0 时把 μ 初始化为 0，并将异常记录替换为 μ/3，那么补偿结果会持续为 0；若这些补偿值又被写回统计样本池，新的 μ 仍为 0，形成无法自行恢复的数学自锁。

错误的自锁链路n₀ = 0 → μ₀ = 0
x* = μ₀/3 = 0
μ₁ = mean({0}) = 0后续记录继续被替换为 0，基线永远无法形成。
正确的冷启动原则基线未就绪 → x* = x
只采集原始值，不自动判异常μ/3 只能是基线成熟后的业务补偿结果，不能用于生成基线。

必须隔离两套数据

原始基线池保存清洗后的 raw_duration，用于计算 P05、P95、μ、σ；永远不写入 μ/3 等补偿值。
→
规则判定层读取已发布阈值，对当前记录生成正常、异常或待定状态。
→
有效结果池保存 effective_duration，仅用于报表和答卷时长汇总，不反向污染基线。
关键约束

阈值只能由原始基线池计算。补偿时长、截尾时长和人工修正值不得参与下一轮百分位与均值计算，否则会产生反馈偏差甚至再次自锁。

冷启动状态机

阶段样本量阈值来源判定策略
C0 未初始化n = 0上级先验或业务默认值没有任何先验时只采集，统一显示“待定”，不执行 μ/3
C1 采集期1 ≤ n < 50上级分组/同类题型先验可以提示风险，但不自动拦截或替换；原始值持续进入基线池
C2 预热期50 ≤ n < 200当前样本与先验加权生成临时阈值，异常进入人工审核，不直接作为最终质量结论
C3 稳定期n ≥ 200当前同质分组经验百分位正式启用 P05/P95 自动规则，并记录规则版本

初始值的获取顺序

  1. 同问卷版本、同题目、相近车型的历史分布。
  2. 上一级分组，例如车系、品牌或同问卷类型的近 90 天基线。
  3. 同类题型先验，例如单选、多选、矩阵题分别配置默认 P05/P95。
  4. 上线前试跑、测试样本或灰度流量形成的种子基线。
  5. 上述数据全部不存在时进入纯采集模式，不自动生成统计异常。
均值先验收缩μ̃ = (n·μ样本 + k·μ先验) / (n+k)n=0 时 μ̃=μ先验，不会得到无意义的 0；k 为先验强度。
分位阈值加权T̃ₚ = w·Qₚ(样本) + (1−w)·Qₚ(先验)
w = n/(n+k)样本增加后，阈值自动从先验平滑过渡到当前分组。

基线未就绪时的有效时长

防自锁处理xᵢ* = { xᵢ，baseline_ready = false； min(xᵢ,T题,95)，baseline_ready = true }未就绪时保留清洗后的真实值；就绪后推荐使用 P95 截尾。若必须兼容 μ/3，只有在 baseline_ready=true 且 μ>0 时才允许执行。

冷启动期间仍可配置与数据无关的硬性安全边界，例如负值、0 秒、超过会话超时的记录直接判为系统无效；这些边界不得冒充统计百分位。

冷启动专项验收

n=0 时不产生 μ/3=0 的补偿记录。
第一条合法非零时长能够进入原始基线池。
补偿值不会反向参与 μ、σ、P05、P95 计算。
σ=0 或所有样本相同时显示“待定”，不默认正常。
上级先验缺失时自动进入只采集模式。
达到样本门槛后按版本切换为正式百分位规则。

系统落地方案

阈值计算、实时判定、接口字段和规则版本需要形成完整闭环。

数据处理链路

清洗剔除预览、未提交、负值、缺失时间和系统异常。
→
计算按 group_key 计算 P05、P95、样本量和窗口。
→
审核返回状态、分位、阈值、原因和规则版本。

百分位的增量更新

重要限制

只保存 n、均值 μ 和标准差 σ，无法准确恢复 P05、P95。原来的均值/标准差补偿公式不能替代百分位更新。

数据规模建议方式
中小规模每天或每小时按分组排序，精确重算百分位
大规模使用 t-digest、KLL Sketch 或数据仓库 approx_percentile
需要审计保存阈值、样本量、窗口、分组键、算法和规则版本
09

上线步骤与验收标准

通过历史回放验证规则效果，再逐步切换人工审核主规则。

回放最近 30～90 天数据，比较新旧规则命中差异。
确认 P05 在各分组中覆盖约 5% 的有效历史样本。
检查秒/分钟及 0.05/5% 的转换是否统一。
对比人工审核命中率、误报率和异常覆盖率。
验证问卷版本变更后不会复用旧版本阈值。
确认阈值缺失时显示“待定”而不是“正常”。
保存 rule_version，支持历史结果重放和审计。
监控各分组异常率，避免小样本造成突变。

推荐最终规则

冷启动：基线未就绪 → 原始值只进入基线池，状态为“待定”，禁止执行 μ/3

题目级：基线就绪后，超过同组经验 P95 → 按 P95 截尾，或按已确认的补偿规则处理

答卷级：低于或等于同组经验 P05 → 标记“答题过快”，进入人工审核

兜底：样本不足、阈值缺失或计算失败 → 标记“待定”，禁止默认返回“正常”
