# 卡券配置与领取系统 · 产品原型

依据工作区的《卡券配置与领取系统 · 产品需求清单（PRD）》制作，并结合活动中心交接资料中的后台 UI 规范、活动与卡券关联规则及专题原型。直接打开 `index.html` 即可预览；GitHub Pages 入口为本目录的 `index.html`。

## 页面

- 总览：活动、卡券及演示数据概览，业务流程入口。
- 功能清单：PRD R1–R8、异常与边界、当前实现状态。
- 活动管理：列表、筛选、新建、编辑、查看、上线/下线、领取页入口；基础配置与页面配置。
- 卡券管理：列表、筛选、新建、编辑、查看、启停；基本信息、领取规则、核销规则、关联设置和提醒。
- 素材配置：头图、背景图、券卡图与文案；图片在当前浏览器内保存。
- 数据看板：活动 UV、领取人数、各券量、领取率与统计口径。
- 领取记录：脱敏手机号、券码、核销状态，支持脱敏 CSV 导出。
- 账号权限：管理员、运营和 C 端用户的最小权限矩阵。
- C 端领取页：H5 移动端预览、二选一/多选一/多选多、库存和时段限制、领取结果、已领只读态。

## 原型边界

这是独立静态产品原型，活动、卡券和领取记录使用浏览器 `localStorage` 保存。手机号只在本机计算 SHA-256 哈希并保留脱敏值，建议仅使用测试号码。示例已发量是展示基线，数据看板会把它与本机领取记录分开展示。不同浏览器之间不共享状态。

上线真实业务前需接入服务端数据库、短信验证码/小程序微信手机号授权、服务端时间、事务或条件更新的库存与次数原子扣减、幂等请求处理、正式文件存储、鉴权与 RBAC，以及 DACC/DMS 核销状态回写。静态页面无法提供这些服务端保证。

PRD 未要求的无代码拖拽、支付和核销闭环不在首版原型中。活动中心交接资料中的号码级准入、商城互斥叠加等扩展规则仅用于后续接口讨论，未冒充为本原型已实现的正式功能。
